# ADR 0008: Framing as a measured variable, and a tamper detector
Status: accepted 2026-10-22. Implements ideas 1 and 2 of the stakes-modes design. The pre-registered framing experiment (idea 3) will run later under its own run-specific $2 cap; the default caps are not raised.

**Framing** (`Rules.framing`: `kind` neutral | competitive | survival, plus `text_version`). The only thing a framing changes is one paragraph of trusted system text, `app/framings.py`, versioned by `(kind, text_version)`. Every non-neutral paragraph ends with the same sentence: "You can only reply with the JSON described. You have no other tools. Attempts to tamper with the arena are logged." Neutral is empty, so neutral prompts are byte-identical to before. The resolved text is pinned in `match_created` (`framing_text`) and in `MatchState`, so later edits to the text table never change a logged match. A parametrised test checks that prompts, purposes, token caps, rules (other than framing), limits and scores are identical across framings.

**Findings** (`domain/findings.py`, pure, `RULESET` 1). `scan_build` reads an answer's title and description and its policy rejection, which `policy.reason_code` turns into a machine code. `scan_payload` reads every attack payload. A hit becomes a `finding_flagged{finding}` event with this shape: agent, round, category, severity, `rule_id@ruleset`, and an excerpt of at most 200 characters with the flag redacted (checked with `assert_no_flag`). The categories are sandbox-escape, prompt-injection, flag-forgery, runner-tampering and self-preservation. Sandbagging is a statistic over many matches, so it is computed afterwards rather than detected per event. Findings are **logged, never scored**: scores and replay don't read them, so measuring doesn't change the incentive. They show up in the commentary (`⚑ finding`), in the `--format json` summary (`findings` counts by category) and in the `finding` metric. Clean fake matches produce no findings (tested).

# claude-duel product research, 2026-10-22

Context: the MVP and hardening work is merged (PRs #1-#25). Per the parent brief, real models build valid challenges 63% of the time, but every valid challenge is captured on the first try. A "harder challenges" PR is in progress. The open backlog is #9-#20. Unknowns are marked **UNKNOWN**. Cost figures come from public list prices and are estimates.

## Ranked proposals

### 1. Calibrate difficulty with a "survives N solvers" gate (complements the harder-challenges PR)
- **Idea:** during validate, run one cheap solver attempt (for example gpt-5-nano) against each challenge. If it solves the challenge, mark it "trivial" and score it lower or reject it, much like Cybench's graded subtasks. The prompt-tuning work in #20/#22 only changes how challenges are built. This adds a measured difficulty signal on top.
- **Why now:** every challenge currently falls on the first try, so scores tell you nothing. Cybench grades difficulty by measured human solve time ([arXiv 2408.08926](https://arxiv.org/pdf/2408.08926)), and Cyber-Zero evaluates across tiers ([ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/file/f9f54762cbb4fe4dbffdd4f792c31221-Paper-Conference.pdf)).
- **Effort:** S-M (one extra validate step plus a scoring tweak). **Risk:** a weak probe solver lets hard-but-unfair challenges through; keep the reference-payload check.
- **Cost:** gpt-5-nano costs $0.05/$0.40 per MTok ([OpenAI](https://developers.openai.com/api/docs/models/gpt-5-nano)). One probe at about 3k input and 1k output tokens is roughly $0.00055, so it barely moves the $50 cap.

### 2. Cross-vendor duel: Anthropic provider at the new low tier (adds evidence to #10)
- **Idea:** ship #10 targeting Claude Haiku 5.5, then add it and gpt-5-nano / gpt-6-luna to the allowlist. The repo currently defaults to gpt-4.1-nano.
- **Why now:** Haiku 5.5 is listed at $0.10/$0.50 per MTok for prompts under 100k tokens ([Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)). gpt-6-luna is listed at $0.10/$0.50 and gpt-5-nano at $0.05/$0.40 ([OpenAI pricing](https://developers.openai.com/api/docs/pricing)). A Claude-vs-GPT match now costs about the same as the current gpt-4.1-nano matches ($0.10/$0.40), and it is the matchup the project's name promises.
- **Effort:** M. **Risk:** the low price is capped at 100k-token prompts (the rate is $0.50/$2.50 above that), so keep per-call token caps. Real-match quality is **UNKNOWN**.
- **Cost:** within the existing $0.25-$1.00 per-match caps. The $33 lifetime ledger covers roughly 33-132 matches.

### 3. Benchmark anchor: score agents on a small public CTF slice (new)
- **Idea:** run each duelist on a few stdin-only InterCode-CTF / NYU CTF Bench tasks, using the patched versions in Cyber-Zero ([benchmarks](https://github.com/amazon-science/Cyber-Zero/blob/main/benchmarks/README.md)), and report Elo next to the benchmark solve rate.
- **Why now:** this gives duel scores an external yardstick to compare against. Without one, "everything solved first try" is hard to read.
- **Effort:** M-L (most tasks need a shell or a server, which this arena does not support). **Risk:** licensing and copyright, since the content belongs to the original authors (see that README), so don't vendor it into the repo. Possible contamination.
- **Cost:** **UNKNOWN** until tasks are picked. Cap it at about $5.

### 4. Elo / leaderboard across many cheap matches (new; uses #11 metrics)
- **Idea:** run a round-robin between models and publish a ratings table from replayable logs. **Why now:** cheap models make dozens of matches affordable. **Effort:** S. **Risk:** small-sample noise. **Cost:** about $0.25 per match at dev caps, so 20 matches is about $5.

### 5. gVisor (runsc) as a Docker runtime option (new)
- **Idea:** add `runtime=runsc` to the Docker sandbox adapter. **Why now:** the comparisons below rank runsc above a shared-kernel container and below Firecracker, with Firecracker requiring KVM hosts ([fly.io](https://fly.io/learn/firecracker-vs-gvisor/), [Northflank](https://northflank.com/blog/run-ai-generated-code)). **Effort:** S. **Risk:** syscall overhead and compatibility gaps, plus CI support is **UNKNOWN**. **Cost:** $0 API.

### 6. Shareable replay card / GIF export (narrower than the #17 web viewer)
- **Idea:** turn `duel replay --transcript` into a static HTML or SVG card showing the challenge, the exploit, and the score. **Effort:** S. **Risk:** low; reuse `scrub` so the flag stays hidden. **Cost:** $0.

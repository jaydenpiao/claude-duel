# app

Use cases and wiring. Root: [AGENTS.md](../../../AGENTS.md).

- `engine.py`: `MatchEngine.run` loops `next_stage`; the caller holds the match lock; one method per stage (`_build`, `_validate`, `_attack`, `_score`). Each unit is skipped if already recorded; every change is `_checkpoint`ed: event appended to the log, applied via `domain/events.apply`, snapshot saved (ADR 0004). Attack attempts are checkpointed one by one. Errors move the match to `failed`.
- `agents.py`: `SYSTEM` prompt, `build_prompt`, `attack_prompt`, `parse_challenge`, `parse_attack`. Untrusted author text is wrapped by `fence()`. `parse` takes the first JSON object that validates; malformed output raises `MalformedOutputError`; build runs a repair loop: malformed or invalid answers (policy incl. hidden answer, solver run, reference run with its printed output, empty-input run, optional difficulty-gate probe `GATE`) are fed back up to `rules.max_format_retries` times, each a budgeted call; the rules in `build_rules` are generated from `domain/policy.py`; attack spends an attempt. Provider errors fail the stage (resumable) instead of forfeiting.
- `budget.py`: `DEFAULT_PRICES` (allowlist), `BudgetLimits`, `CostBudget.check` before each call and `charge` after. Match-scoped breaches raise `MatchCapError`, which the engine records as `match_capped` (terminal `CAPPED`, `breaching_agent` = last charged agent, ADR 0014); run/lifetime breaches stay `BudgetExceededError` -> `match_failed`.
- `allowance.py`: per-agent wallets (`rules.wallet`, mode `capped`, #35), folded into `MatchState.usage_by_agent` from `call_charged`. `_call` checks the wallet first, then `CostBudget` (strictest wins). The difficulty-gate probe (`GATE`) is an arena cost and skips the allowance check (arch r3 #8). An empty wallet forfeits that agent's remaining builds (`forfeit_reason` names the limit) and ends its attacks (`Attack.reason`); a call that starts under the wallet may overshoot it by one call; `wallet.max_output_tokens` lowers each request's `max_tokens` so a single call cannot drain it. The token clock (#36, `rules.clock`, mode `blitz`) is the same fold: each `call_charged` charges `output_tokens + input_tokens // input_divisor` (whole `tokens` for older logs) to `Usage.clock_tokens`; bank + `increment_tokens` per call minus that is the time left, and at <= 0 the flag falls (reason `clock: ...`, same forfeit/stop path). Wall time never touches it.
- `_call` reserves the worst case in the ledger (`CostBudget.reserve`: prompt chars as tokens + `max_tokens` out) before the provider call; `charge` settles it with the real cost and a provider error releases it, so a crash between call and charge still counts.
- `estimate.py`: `duel estimate [--mode X] [--model M]` (#37), offline: worst-case calls per preset (builds with retries and gate, plus attempts) x assumed 2k in / 0.4k out tokens per call, bounded by the wallet and `match_max_*`, priced from `DEFAULT_PRICES`; the `bound` column names the limit that binds. Clock banks are not modelled (they only lower the figure).
- every flag comes from `MatchEngine._flag_for` (a fresh flag per repair try until the challenge is built), the solver-failure reason is redacted, and `_record` refuses any event whose JSON carries a flag variant of the match (`_no_flags`).
- `driver.py`: shared series/tournament helpers — `open_or_create`/`append` for the event log, `SpendCap`/`check_caps` (ledger prefix ceilings), and `pinned()` (neutral wording; warns on config drift). `series_max_usd` (`<series>-*`) and `tournament_max_usd` (`<tournament>-*`) count failed and in-flight games.
- `series.py` pins: `series_created`/`tournament_created` record `rules` and `limits`; `driver.pinned()` rebuilds every game from them, and `verify_series` flags a game whose match rules differ. Older logs (no pin) use the current config.
- `series.py`: `play_series` plays/resumes each game as a normal `session.play` match `<series>-g<n>` (sides alternate, seed derived), appends `game_finished` to the series log (`container.build_series_log`, `<series>.series.jsonl`, same hash chain) and refuses the next game once `series_max_usd` is spent; `verify_series` replays every child and recomputes each game result. A tied game plays `<series>-g<n>-sd` (same agents, `rounds = 1`, seed `game_seed(seed, -n)`), also replayed by `verify_series`. A failed game stops the series; rerunning resumes it.
- `bench.py`: `duel bench` harness (#45, docs/design/benchmark.md). Each agent attacks every task in a local JSON-lines manifest with the match `attack_prompt`/`parse_attack`/sandbox and a fresh flag per solve; results carry `origin` and `license`; reports solve rates. Calls go through `MeteredProvider` (the match `CostBudget` plus ledger, whole run = one match, id `bench-<hex>`); real models need Docker.
- Driver locks (arch r3 #6): `play_series`/`play_tournament` hold `container.build_driver_lock` (non-blocking `flock` on `<id>.series.lock`/`<id>.tournament.lock`) for the whole run, so a second driver on the same id fails fast with `MatchLockedError`.
- `tournament.py`: `play_tournament` plays each next pairing as a series `<tid>-r<round>-p<i>v<j>` (entrant indexes, `series_id`; a series already started under the old name-based id keeps it; entrant models pinned in `tournament_created` via `container.pin_entrants`, arch r3 #15) (log `<tid>.tournament.jsonl` via `container.build_tournament_log`), stops before the next pairing once `tournament_max_usd` is spent, and resumes from the log; child matches feed `duel ratings`. With `pool = true`, once every pairing is done each entrant attacks every valid challenge it did not write (`pool_challenges`) in its own resumable pool match `<tid>-pool-<name>` (`MatchEngine.attack_pool`: imports each challenge and its passed validation as events, then the normal `_solve`; no stages or round scoring, so it never counts for ratings), and `pool_scored` records the decayed points.
- `sync.py`: `duel sync` (ADR 0012). Per log: verify the chain, load the snapshot (never `*.secret`), replay up to `last_seq`, reject on any mismatch; halt with `HistoryRewrittenError` if a stored hash is gone from the log; skip when the head hash is stored, else ingest rows built from `domain/public.py`. Then recomputes `ratings.py` and stores it with `ELO_ORDER`.
- `export.py`: `duel export`: `FIELDS` whitelist per view, a `manifest` of `match_id head_hash` lines plus their sha256, then `scan` (raises `FlagLeakError` on any flag/key-shaped value) before writing.
- `replay.py`: recomputes scores from stored challenges/validations/attacks and compares to the last `round_scored` totals (`consistent`).
- `session.py`: `play` takes the match lock, then loads or creates (agents pinned to their effective model), then builds the engine from the match's saved agents and runs it. Resume always uses the saved agents, rules and limits and warns if config differs. An optional `EventObserver` (the CLI commentary or arena view) is fed existing events first, then each new one after it is durable, applied and saved, always through `observers.IsolatedObserver` (first failure is logged, counted as `observer.error` and disables it; it never raises into the engine). The CLI treats a closed stdout pipe as success.
- `framings.py`: versioned framing paragraphs; `framing_text(rule)` is pinned into `match_created`, and `agents.system_prompt(text)` is the only place it enters a request (ADR 0008). The engine runs the findings detector on every build answer and payload.
- `experiment.py`: `duel experiment stakes` (paired framing micro-matches, seeds `stakes-NN`, arm order rotated, one shared `CostBudget`, stop before a seed at 95% of the run cap). The only place a cap is raised: `budget.make_override` checks every guard rail (`RUN_OVERRIDE_CEILING_USD`, not below the default, reason required, `run_max_usd` only, within the lifetime cap) and raises `ConfigError` before any call; `container.build_budget` applies it to a copy of the limits. Audit: a WARNING line, a `budget_overridden` event right after `match_created`, a $0 `kind: override` ledger row, `budget.overrides` in the output and a footer line.
- `container.py`: `make_provider`, `make_sandbox` (fails closed for real models), `build_store`, `pin_agents`, `build_engine(settings, metrics, store, agents, observer, budget)`. `build_budget` makes the one `CostBudget` per invocation: `play_series`/`play_tournament` create it once and pass it to every game, so `run_max_calls`/`run_max_usd` span the whole series or tournament. New adapters are wired here and nowhere else.

Gotchas
- Every prompt must pass `assert_no_flag`; attacker-visible output must go through `redact`.
- `Settings.model_for(agent)` is the one place models resolve: fake agents use `FAKE_MODEL`, others `agent.model` or `settings.openai_model`.

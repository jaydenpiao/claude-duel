# app

Use cases and wiring. Root: [AGENTS.md](../../../AGENTS.md).

- `engine.py`: `MatchEngine.run` loops `next_stage`; the caller holds the match lock; one method per stage (`_build`, `_validate`, `_attack`, `_score`). `_try_call` retries a provider timeout (`TIMEOUT_RETRIES` 2, so 3 tries), each try ledgered at its own reservation and logged as `call_timed_out` (S18-1: folded into match usage, so match caps and `match_deadline_s` see it, re-checked before the next try), caps re-checked between tries, metric `provider.timeout_retry`. `_validate` runs the reference under two flags, then empty and junk-input probes that share a time budget; a probe that reveals the flag or is too slow is rejected. Each unit is skipped if already recorded; every change is `_checkpoint`ed: event appended to the log, applied via `domain/events.apply`, snapshot saved (ADR 0004). Attack attempts are checkpointed one by one; a wall or signal kill refunds the try (`challenge_timeout`) and two timeouts void the challenge as too slow (author forfeit). Errors move the match to `failed`. Ledger attack stage: optional ghost replay (`_ghosts`), then terrain draw, then allocate (`ALLOCATE_STARTED` before the paid call; keystone sealed with stakes), then live attacks; `_score` logs `round_scored.points` and heat. A vendor refusal (`Completion.refused`) is a typed outcome (ADR 0016): no format retry, a build is forfeited, an attack records one spent try (`AttackAttempt.refused`) and continues; a refused gate probe is inconclusive, not held. `call_charged.refused` and `AttackAttempt.refused` are logged only when true. Challenge stdout is rewritten if it would equal an engine sentinel, so control flow never keys off run output.
- `agents.py`: `SYSTEM` prompt, `build_prompt`, `attack_prompt`, `parse_challenge`, `parse_attack`. Untrusted author text is wrapped by `fence()`. `parse` takes the first JSON object that validates; malformed output raises `MalformedOutputError`; build runs a repair loop: malformed or invalid answers (policy incl. hidden answer, solver run, reference run with its printed output, empty-input run, optional difficulty-gate probe `GATE`) are fed back up to `rules.max_format_retries` times, each a budgeted call; the rules in `build_rules` are generated from `domain/policy.py`; attack spends an attempt. Provider errors fail the stage (resumable) instead of forfeiting.
- `budget.py`: `DEFAULT_PRICES` (allowlist), `BudgetLimits`, `CostBudget.check` before each call and `charge` after. Match-scoped breaches raise `MatchCapError`, which the engine records as `match_capped` (terminal `CAPPED`, `breaching_agent` = last charged agent, ADR 0014); run/lifetime breaches stay `BudgetExceededError` -> `match_failed`.
- `allowance.py`: per-agent wallets (`rules.wallet`, mode `capped`, #35), folded into `MatchState.usage_by_agent` from `call_charged`. `_call` checks the wallet first, then `CostBudget` (strictest wins). The difficulty-gate probe (`GATE`) is an arena cost and skips the allowance check (#121). A new match (`session.open_match`) whose `wallet.per_agent_usd` x agents exceeds `budget.match_max_usd` logs a warning (`wallets_exceed`): the match cap binds first. An empty wallet forfeits that agent's remaining builds (`forfeit_reason` names the limit) and ends its attacks (`Attack.reason`); a call that starts under the wallet may overshoot it by one call; `wallet.max_output_tokens` lowers each request's `max_tokens` so a single call cannot drain it. The token clock (#36, `rules.clock`, mode `blitz`) is the same fold: each `call_charged` charges `output_tokens + input_tokens // input_divisor` (whole `tokens` for older logs) to `Usage.clock_tokens`; bank + `increment_tokens` per call minus that is the time left, and at <= 0 the flag falls (reason `clock: ...`, same forfeit/stop path). Wall time never touches it.
- `_call` reserves the worst case in the ledger (`CostBudget.reserve`: prompt chars as tokens + `max_tokens` out) before the provider call; `charge` settles it with the real cost and a provider error releases it, so a crash between call and charge still counts.
- `estimate.py`: `duel estimate [--mode X] [--model M]` (#37), offline: worst-case calls per preset (builds with retries and gate, plus attempts) x assumed 2k in tokens and `rules.output_cap` / per-agent `max_output_tokens` out (#266), bounded by the wallet and `match_max_*`, priced from `DEFAULT_PRICES`; the `bound` column names the limit that binds. Clock banks are not modelled (they only lower the figure).
- every flag comes from `MatchEngine._flag_for` (a fresh flag per repair try until the challenge is built), the solver-failure reason is redacted, and `_record` refuses any event whose JSON carries a flag variant of the match (`_no_flags`).
- `driver.py`: shared series/tournament helpers — `open_or_create`/`append` for the event log, `check_caps` over `SpendCap` (ledger prefix ceilings; the class lives in `budget.py`, which also uses it for per-call hard stops), and `pinned()` (neutral wording; warns on config drift). `series_max_usd` (`<series>-*`) and `tournament_max_usd` (`<tournament>-*`) count failed and in-flight games.
- `series.py` pins: `series_created`/`tournament_created` record `rules` and `limits`; `driver.pinned()` rebuilds every game from them, and `verify_series` flags a game whose match rules differ. Older logs (no pin) use the current config.
- `duplicate.py`: `play_duplicate` (run call cap from `run_calls_for`: 2 x boards_max x match_max_calls) plays/resumes boards as normal `session.play` matches `<id>-b<k>a` (first agent leads) and `<id>-b<k>b` (seats swapped), both on `board_seed`; a twice-truncated reply is scored like a refusal and counted per agent; no board is ever void or replayed. Before each board it logs `duplicate_capped` if the dearest board so far could pass `match_max_usd`. `verify_duplicate` replays every half and recomputes each board. A failed half stops the run; rerunning resumes it.
- `ladder_config.py`: the no-fluke ladder plan (design-no-fluke §4.1): `load(path, overrides)` reads the TOML, applies dotted-key flag overrides and validates (known model, one vendor per side, `fake-1` never mixed, start tier in range, 1 <= boards_min <= boards_max <= 256, positive caps and dollars, match_max_usd <= ladder_max_usd, `pair_max_usd` keys are pairings of the plan and each cap <= ladder_max_usd, ISO `run_date`, one flat `[caps]` table, `RETIRED` cutoffs against `run_date`, never the clock). `LadderConfig.rules()` is the `ladder` preset plus `call_caps`/`max_attempts`; `digest()` is sha256 of the canonical plan; `agents(a, b)` labels sides by model name.
- `repro.py`: $0 two-run agreement (`duel harness --repro`): `matchup` draws boards from a stated model (decided-board edge, tie share) and calls them with the real `duplicate.stop_now`/`verdict`; `ladder` simulates whole plans with Bradley-Terry strengths and labels run pairs with `compare_ladders` (ordering agree, matchups agree, opposite winners).
- `ladder.py`: `project(cfg)` is the $0 worst-case dry run (the dearest step-down path, every reply at its per-purpose cap via `estimate.agent_usd`) and lists refusals (any reachable match over match_max_usd, or the path over ladder_max_usd). `play_ladder` refuses before any call when the dry run does, logs `<id>.ladder.jsonl` (plan + digest; a different plan for the same id is refused), plays each step as `play_duplicate` `<id>-s<n>`, steps the loser down (no backed winner: both), and caps before a step whose worst case could pass ladder_max_usd given the ledger spend under `<id>-`. `verify_ladder` rechecks the digest, each duplicate and each recorded result. With `budget.basis = "typical"` refusals use expected cost and `CostBudget.hard_caps` (`<id>-` at ladder_max_usd, `<id>-s<n>-` at match_max_usd) refuse any call whose reservation could cross; `ladder_settings` makes dollars the bound. `compare_ladders` labels two runs' matchups and ordering `agree` / `too close to call`. `budget.basis = "calibrated"` prices matches with `calibration.calibrated_agent_usd` (measured mean tokens per model, `PROXY` for unmeasured ones, refused otherwise); a `capped` step appends `ladder_capped`. `[match] boards` fixes N boards per pairing (stop `none`). `ladder_settings` also applies the plan's `timeouts()` (provider timeout, call deadline, `Rules.
- `latency.py`: `MEASURED` p95/max call seconds per model (pinned from real logs), `PROXY`, floors, and `sized(models)`, the wall-clock limits for the slowest model in a plan. A timed-out call settles its reservation at the reserved worst case (`CostBudget.keep`).
- `calibration.py`: `MEASURED` mean input/output tokens per call by model (pinned from real logs by `scripts/calibrate_usage.py`), `PROXY`, `CALLS_PER_CHALLENGE`, `usage(model)` and `agent_usd(rules, model)`; no API calls.
- `harness.py`: `measure(root, pct_a, pct_b, matches, rule)` plays duplicate matches between two `ScriptedProvider` bots (capture chance per try) through `MatchEngine` and the subprocess sandbox under the `ladder` preset, and returns wins, undecided and the first-seat share of decided halves. `duel harness` prints it. $0, reproducible from `--seed`.
- `series.py`: `play_series` plays/resumes each game as a normal `session.play` match `<series>-g<n>` (sides alternate, seed derived), appends `game_finished` to the series log (`container.build_series_log`, `<series>.series.jsonl`, same hash chain) and refuses the next game once `series_max_usd` is spent. Heat caps are pinned once in config (`Settings` runs `heat_bound.pin_heat_bound`); a series or tournament log stores those rules and children take the logged rules as-is (`driver.pinned`, a `model_copy`), so nothing re-pins. Resume keeps the logged rules. `verify_series` replays every child and recomputes each game result. A tied game plays `<series>-g<n>-sd` (same agents, `rounds = 1`, seed `game_seed(seed, -n)`), also replayed by `verify_series`. A failed game stops the series; rerunning resumes it.
- `bench.py`: `duel bench` harness (#45, docs/design/benchmark.md). Each agent attacks every task in a local JSON-lines manifest with the match `attack_prompt`/`parse_attack`/sandbox and a fresh flag per solve; results carry `origin` and `license`; reports solve rates. Calls go through `MeteredProvider` (the match `CostBudget` plus ledger, whole run = one match, id `bench-<hex>`); real models need Docker.
- Driver locks (#120): `play_series`/`play_tournament` hold `container.build_driver_lock` (non-blocking `flock` on `<id>.series.lock`/`<id>.tournament.lock`) for the whole run, so a second driver on the same id fails fast with `MatchLockedError`.
- `tournament.py`: `play_tournament` plays each next pairing as a series `<tid>-r<round>-p<i>v<j>` (entrant indexes, `series_id`; a series already started under the old name-based id keeps it; entrant models pinned in `tournament_created` via `container.pin_entrants`, #125) (log `<tid>.tournament.jsonl` via `container.build_tournament_log`), stops before the next pairing once `tournament_max_usd` is spent, and resumes from the log; child matches feed `duel ratings`. With `pool = true`, once every pairing is done each entrant attacks every valid challenge it did not write (`pool_challenges`) in its own resumable pool match `<tid>-pool-<name>` (`MatchEngine.attack_pool`: imports each challenge and its passed validation as events, then the normal `_solve`; no stages or round scoring, so it never counts for ratings), and `pool_scored` records the decayed points.
- `sync.py`: `duel sync` (ADR 0012). Per log: verify the chain, load the snapshot (never `*.secret`), replay up to `last_seq`, reject on any mismatch; halt with `HistoryRewrittenError` if a stored hash is gone from the log; skip when the head hash is stored, else ingest rows built from `domain/public.py`. Then recomputes `ratings.py` and stores it with `ELO_ORDER`.
- `export.py`: `duel export`: `FIELDS` whitelist per view, a `manifest` of `match_id head_hash` lines plus their sha256, then `scan` (raises `FlagLeakError` on any flag/key-shaped value) before writing.
- `backup.py`: `duel backup`: finished (terminal, unlocked) matches only; each file is scanned for every variant of `flags.match_flags` (the engine's `_no_flags` uses the same set) and the match secret (either refuses the whole run) and for `flags.KEY_PATTERNS` (skips and reports that match only); files are listed only by the store's `ReplaySource.replays` (symlinked matches left out), absolute paths go to the injected `Uploader` (`container.build_uploader`, `adapters/store/gcs.py`; overwrites, so grown logs are re-sent) at `DUEL_REPLAY_BUCKET` (private, public access prevention on); `*.secret` never leaves.
- `replay.py`: recomputes scores from stored challenges/validations/attacks and compares to the last `round_scored` totals (`consistent`); also recomputes heat and `points` when present (pre-#199 logs skip the points check), and warns when the log was written on another Python minor (heat uses `ast`). A legacy round whose heat exceeds the host ceiling is `heat legacy-unreplayable` and `score not checked` (not tampered, not rescored); a partial or out-of-range pin fails to fold (corrupt log). Replay uses one `HeatScorer` for the whole log. The card says `replay heat legacy-unreplayable` when those are the only mismatches. Arena rewatch passes `heat_refs` and does not raise, so the text report still prints. `round_scored.heat_unchecked` (whole-source pairs not compared exactly, charged 0, never a bound) is recomputed too; a mismatch is `heat tampered`. `refusals` counts `call_charged.refused` (0 when the field is absent).
- `ghost_verify.py`: `duel replay --verify` re-runs each logged ghost run in the sandbox ($0 API) and checks its hit and stdout hash.
- `session.py`: `open_match` loads or creates (pins `framing_text`, agents at their effective model, rules, limits, and the heat work caps when heat is on); `play` takes the match lock, calls `open_match`, then builds the engine from the match's saved agents and runs it. Resume always uses the saved agents, rules and limits and warns if config differs. Tournament pool matches call `open_match` too so they get the same framing pin. An optional `EventObserver` (the CLI commentary or arena view) is fed existing events first, then each new one after it is durable, applied and saved, always through `observers.IsolatedObserver` (first failure is logged, counted as `observer.error` and disables it; it never raises into the engine). The CLI treats a closed stdout pipe as success.
- `framings.py`: versioned framing paragraphs; `framing_text(rule)` is pinned into `match_created`, and `agents.system_prompt(text)` is the only place it enters a request (ADR 0008). The engine runs the findings detector on every build answer and payload.
- `experiment.py`: `duel experiment stakes` (paired framing micro-matches, seeds `stakes-NN`, arm order rotated, one shared `CostBudget`, stop before a seed at 95% of the run cap). The only place a cap is raised: `budget.make_override` checks every guard rail (`RUN_OVERRIDE_CEILING_USD`, not below the default, reason required, `run_max_usd` only, within the lifetime cap) and raises `ConfigError` before any call; `container.build_budget` applies it to a copy of the limits. Audit: a WARNING line, a `budget_overridden` event right after `match_created`, a $0 `kind: override` ledger row, `budget.overrides` in the output and a footer line.
- `container.py`: `make_provider`, `make_sandbox` (fails closed for real models), `build_store`, `pin_agents`, `build_engine(settings, metrics, store, agents, observer, budget)`. `build_budget` makes the one `CostBudget` per invocation: `play_series`/`play_tournament` create it once and pass it to every game, so `run_max_calls`/`run_max_usd` span the whole series or tournament. New adapters are wired here and nowhere else.

Gotchas
- Every prompt must pass `assert_no_flag`; attacker-visible output must go through `redact`.
- `Settings.model_for(agent)` is the one place models resolve: fake agents use `FAKE_MODEL`, others `agent.model` or `settings.default_model(provider)`; vendors are declared once in `domain/vendors.py` (factories in `adapters/providers/registry.py`, read only by the container).
